Nikon UVC-PTP Bridge

One process owns the camera: PTP-style control plus a single video consumer, then re-publish frames to other apps through a virtual camera (or similar) instead of fighting the stock webcam driver.

Why this exists

Nikon’s utilities often assume a single client. Mixing the UVC webcam driver with tethering-style control frequently fails because the firmware, class drivers, or companion apps contend for the same USB functions. This project aims to consolidate access in one service layer, then expose video and control through stable, composable surfaces.

Target layering

  1. Physical USB — WinUSB or still-image negotiation so only the bridge opens the device.
  2. Demux — read UVC-style video (or PTP live view where applicable) and PTP control channels in one coordinator.
  3. Virtual sink — Windows Media Foundation virtual camera, DirectShow filter, or OBS VirtualCam-style output so Zoom, Teams, and OBS see one predictable device owned by the bridge.
  4. Control API — local IPC today; optional HTTP or gRPC for companion tools later.
